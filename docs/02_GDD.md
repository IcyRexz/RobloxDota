# Game design document

Co-op base-defense shooter (owner decision 2026-10-20; brief in `docs/01_BRIEF.md`). Numbers marked *(carried)* come from the MOBA prototype code in `src/shared/Config.luau` and are starting points only. Anything marked **OPEN** waits for an owner decision; do not invent it. Keep this file and `Config.luau` consistent as systems land.

## Structure of a session
Hub -> mission (continuous tug of war until one core falls; owner 2026-10-21, replacing build phases and waves) -> Results -> back to Hub.

- **Hub:** shared area in the same place as the mission arena (owner decision 2026-10-20). Players pick a hero, equip unlocked gear and stand on a queue pad (or similar) to start a mission. Map choice limited by class level.
- **Party size:** 1–5 players per mission. Server capacity 5 (to confirm when the hub is built; with one shared arena only one mission runs per server).
- **Mission state flow:** Hub -> Briefing (short countdown; leaving cancels) -> Fighting (continuous tug of war) -> Results -> Resetting -> Hub. Every match has an epoch; delayed callbacks from an older epoch never act. (Was BuildPhase/Wave alternation before the 2026-10-21 tug-of-war redesign.)
- **Win:** the Zombie Core is destroyed (owner 2026-10-21, tug of war; was "final wave cleared"). Whether a boss guards it in the full version: **OPEN**.
- **Lose:** the Base Core is destroyed. Full party wipe: **OPEN**.
- **Leaving mid-mission:** the mission continues for the rest of the party; if the last player leaves it resets. Rewards for leavers: **OPEN**.

## Map layout (mission)
Open battlefield for swarm defence (owner redesign 2026-10-20, replacing the same-day two-lane map; `src/map/`). The map runs along X: our base at negative X is the bottom of the screen, zombies come from positive X at the top. Screen-left is -Z, screen-right is +Z. Simple low-poly graybox style.
- **Battlefield** (`Battlefield.model.json`): 423×420 studs (x -153..270, z -210..210); the base sits flush against its bottom edge (owner 2026-10-20). No lanes, no road strips, no arena walls. The fighting happens roughly between x -150 and 160, z ±130, so the edges are far from it.
- **Landscape** (owner 2026-10-20): rolling grass Terrain from `src/server/Landscape.luau`, at most 6 studs up and 4 down (current map -3.1 to +4.7), flat in and around the base (8-stud margin) and around the zombie core (14 studs; the bake key includes the flat areas, so moving the core asks for a re-bake), easing into hills over 25 studs; our own value noise (fixed seed) instead of `math.noise`, so it can be reproduced outside Roblox. Rojo cannot sync terrain: baking stamps the terrain with a `LandscapeKey` attribute (saved with the place) and the server skips rebuilding when the key matches (rebuilding at every start made clients re-download the ground and stutter, owner report 2026-10-21); otherwise the server builds it at start. The owner runs `require(game.ServerScriptService.Server.Landscape).buildTerrain()` once in the Studio Command Bar (edit mode) so it shows and saves in the place. The `Ground` part is now an invisible, non-colliding bounds marker (minimap, terrain extent). Hills never block attacks (owner). **Trees and rocks are map parts** in `src/map/Nature.model.json` (visible in edit view like the towers), written by `tools/gen_nature.py`, which copies the height formula exactly and stores sample heights that the server checks at start (Output warning if they drift): 251 green placeholder trees (trunk + ball; a one-row forest belt on the north, south and east edges without shadows, plus 14 scattered) and 16 grey placeholder rocks, scattered ones at least 24 studs apart (never corridors). Units walk around trunks and rocks.
- **Boundary:** the base's back fence is the bottom edge; TEMPORARY invisible walls on the other edges and just behind the back wall (`Kind = Boundary`) until natural edges are built (T03a).
- **Base** (`PlayerBase.model.json`, bottom half): stone floor x -150..-70, z -66..66, enclosed by **fences** 9 tall, taller than a character and above jump height (owner 2026-10-20, replacing 8-tall walls; cannot be broken; attacks pass through them). Each fence segment is a collision part (a see-through dark slab in Studio's edit view as a placeholder, hidden in play) (`Kind = Fence`; line of sight and the crosshair skip it via `Targeting.seeThrough`, since Roblox raycasts always hit colliding parts) dressed by `src/server/FenceVisuals.server.luau` with the owner's `assets/FenceModel.rbxmx` repeated along it, or wooden placeholder posts and rails until that file exists. A front fence facing the enemy covers the middle (z -34..34); back and side fences close the rest, leaving two **broad openings** (32 studs each) at the front-left and front-right corners (z ±34..66). A tower guards each opening (`LeftTower` / `RightTower`, x -84, z ±50; 900 HP; knight art). Behind each tower an inhibitor (`LeftInhibitor` / `RightInhibitor`, Kind `Barracks`; x -104, z ±30; 700 HP). `BaseCore` in the centre (x -118, z 0; 1200 HP). Player spawn pad behind the core (x -138). Invisible `Opening` markers mark each gap for the swarm code.
- **Zombie side** (`ZombieBase.model.json`): one zombie spawning core, `ZombieCore`, centred at the back (x 220, z 0; 12×14×12; 1200 HP; dark green) (owner 2026-10-21; was two cores at x 150, z ±70). It does not attack.
- **No objective order** (owner 2026-10-23, removed the MOBA lock rule): every tower, barracks and core can be damaged at any time. **A fallen barracks only stops its own soldiers** (owner 2026-10-23: the zombies no longer get +25% for destroying one).
- **Unit spawns:** our minions spawn just inside the base in front of each barracks; zombies spawn anywhere on a ring 16–60 studs around the zombie core (`Config.Minion.ZombieSpawnMinRadius` / `ZombieSpawnMaxRadius`, open ground only; owner 2026-10-21). A spawn point stops once its source structure falls.
- **Camera:** first person, Roblox's built-in `LockFirstPerson` camera mode (set in `default.project.json`); mouse turns the view, cursor locked to the centre; crosshair in the centre, red over an attackable enemy (`src/client/Crosshair.client.luau`). Owner decisions 2026-10-20: fixed top-down camera removed, then default third person, then first person. No overhead bar on your own character. Shift lock disabled; jump allowed again (owner 2026-10-20; Roblox default jump power 50, about 7 studs high, below the 9-stud fences).
- **Minimap:** bottom-right, fixed orientation (base at the bottom, zombies from the top), shows fences, trees, rocks, structures, units and players (`src/client/Minimap.client.luau`).
- **Placeholders now in (2026-10-20):** forest belt on the edges (first pass of T03a; the invisible boundary stays behind it) and scattered trees/rocks plus hills (first pass of T03b). Final art, cliffs or mountains still to come. Compound build nodes are still planned (placement **OPEN**).

## Players and heroes
- Each player's Roblox avatar is their character (as in the prototype); the server marks it, owns Health/MaxHealth attributes and removes Roblox's default regen *(carried: 600 HP, WalkSpeed 16; respawn now follows the death rules below)*.
- **Health regeneration (owner 2026-10-21):** each class has a natural regen in health per second (`Config.Hero.HealthRegen`), applied by the server every 0.5 s to living heroes below max health, in and out of combat. Shown as "Health Regen" in the Character Menu. Values (owner 2026-10-21; Archer and Warrior go into Config when those classes are built):

  | Class | Role | Health regen |
  |---|---|---|
  | Mage | ranged caster, lowest health | **0.5 /s** (in Config) |
  | Archer | ranged, mobile | **0.75 /s** |
  | Warrior | melee front line, highest health | **1.5 /s** |

  For scale: at 0.5 /s the Mage's 500 HP takes about 17 minutes to refill from empty, so regen tops up chip damage between waves rather than winning fights. Whether regen grows with level, pauses after taking damage, or comes from masteries/gear is **OPEN**.
- **Classes (owner decision 2026-10-21):** three classes, **Mage**, **Archer** and **Warrior**, each with one basic attack, one passive, two active abilities (Q and E) and a mastery grid. The **Mage** (lightning; formerly "Zeus") is built first; Archer and Warrior later. How players choose a class (before the hub exists) **OPEN**.
- **Attack:** each hero has its own basic attack. PC: **aimed at the crosshair (owner 2026-10-20)**. Current Pulse attack: left click fires along the camera's look direction; the server casts the shot itself from the hero's head (sphere radius 1, 24 studs), hits the first enemy on that line, passes through allies, hills and fences, is stopped by trees, rocks and structures, and simply misses if nothing is in range. 40 damage (x Attack picks), 0.75 s cooldown spent on every shot, 0.15 s windup. No auto-walk. **Red marker = a click hits this (owner 2026-10-21):** the client runs the server's own shot rule (`Targeting.castShot`) along the crosshair every frame; if it would hit an enemy, that enemy gets the red ring + outline and the crosshair turns red, and the click fires straight. Only when the straight shot would miss does aim assist apply. **Aim assist (owner 2026-10-20):** an enemy within 24 studs, in line of sight and within 3° of the crosshair (measured to its body edge) gets the red ring + outline and shots aim straight at it; it stays until the crosshair is 5° off; move away and the outline and assist turn off. Click/Tab lock removed. The client only bends the direction it sends; the server still casts the shot. Ammo/mana/reload **OPEN**.
- **Death and revive (owner 2026-10-23; `Config.Hero.Death`, `src/server/Heroes.server.luau`):** at 0 health a hero is **down**: the body lies on its back where it fell and cannot move, act or regenerate; zombies and towers ignore it. The player sees the world in grey and a death panel ("YOU DIED", respawn countdown, revive hint and progress), and the camera orbits the body (mouse to look, wheel to zoom). **Countdown:** 5 s + 1 s per level above 1, at most 20 s; then they respawn at the pad with full health, keeping level, XP and masteries. **Revive:** before the countdown ends, a living ally holding **F for 3 s** within 6 studs of the body stands them back up **where they fell with 30% health**. Each player can be revived **once per match** (later deaths always wait out the countdown; the count resets with the match, T15). Server-checked: the reviver is alive, on our side, near and not the downed player, and the server times the hold itself. **Spawn protection:** 2 s without damage after coming back either way. **Popups for everyone:** "<name> has fallen", "<reviver> revived <name>"; the revived player also gets a "YOU HAVE BEEN REVIVED" banner. **Party wipe:** nothing extra; only the Base Core falling loses (owner 2026-10-23). No other death penalty.

## Enemies and waves
- **Current state (owner 2026-10-21: tug of war, continuous spawning, no waves):** from 5 s after start, the Zombie Core sends a group of 4 **zombies** every 4 s and each standing barracks sends 2 melee + 1 archer (khaki) every 15 s, plus Reinforcements (`Config.Minion.Groups` / `GroupInterval`). Placeholder balance: per minute 60 zombies against 16 melee + 8 archers, a little more zombie strength, so an unpushed front drifts toward our base; heroes and upgrades win ground. Caps per team: 40 soldiers, 70 zombies (`MaxAlive`); a group that would exceed its cap spawns only what fits and the rest is dropped, never queued. A zombie group appears together at one spot on the spawn ring (within 6 studs) and shares a rally point (each zombie within 10 studs of it), so the field fills with separate clusters. Units live until killed (600 s safety despawn for stuck units; was 180 s). Earlier: waves every 25 s (zombies 8, 16, 12 per core, then 24 from the one core). Zombies are all melee on the standard Roblox R15 body at full player size (was 70%, owner 2026-10-20): dark green skin, blood-red torso, muddy green legs, no face, glowing red eyes, both arms stretched forward. Attack: a **bite** (owner approved 2026-10-20, keep): the body leans back, then the upper body and head lunge forward; the shoulder also moves (arms alternate), played on each client from the server's `MinionSwing` event like the archer draw; the damage lands when the claw comes down (`ZombieSwipeHitDelay` 0.3 s) and a zombie killed mid-swing never lands it. Unit caps above (check frame rate). Inhibitor bonus (+25% on later spawns for the side that destroys one) still applies. **Sides (owner 2026-10-20):** just us and the zombies, no colour teams. Team attribute values come from `Config.Teams`: `Defenders` (players, our minions and structures; khaki) and `Zombies` (zombies and zombie cores; dark green). Banners say "WE LOST A …" / "ZOMBIES LOST A …". Health bars stay green for us and red for zombies (ally/enemy, not team colours).
- **Unit stats** (`Config.Minion`; order: health, attack, range, attack speed, movement speed, aggro):

  | Unit | Health | Attack | Range | Attack speed | Move speed | Aggro |
  |---|---|---|---|---|---|---|
  | Zombie | 120 | 12 | 5 (melee) | 1 hit / 1 s | 8 | 20 (was 14; Brute 20, Spitter 28, owner 2026-10-23) |
  | Our melee minion | 173 | 17 | 5 (melee) | 1 hit / 1 s | 8 | 16 |
  | Our archer minion | 115 | 14 | 16 (arrow 60 studs/s) | 1 shot / 1 s (0.3 s draw) | 8 | 22 |

  Our minions were buffed +20% health and attack and given wider aggro on 2026-10-20 (owner: they were walking past zombies). Was melee 120 / 12 / aggro 8, archer 80 / 10 / aggro 16. Another +20% health and attack the same day (owner, after units went full size): melee 144/14 -> 173/17, archer 96/12 -> 115/14.

- **Zombie aggro (owner 2026-10-20):** a zombie goes for whatever enemy is **nearest** within its aggro range (14): our minion, a player or an attackable structure (measured to its side), re-checked every 0.2 s and kept unless something else is 2+ studs nearer. **Retaliation (owner 2026-10-23, replaces "zombies never chase"):** a zombie hit by a hero, soldier or tower goes for that attacker first while it stays within 45 studs (`ZombieChaseRange`, beyond the longest hero ability range 40). If something else hits it and is nearer than its current attacker, it switches, but at most once every 3 s (`ZombieAggroSwitchCooldown`) so it does not flip back and forth; an attacker that dies or leaves the chase range frees it at once. **A zombie already standing and hitting something keeps hitting it** (owner 2026-10-23): being hit then neither draws nor switches its aggro; retaliation applies only while it is walking or idle. Zombies still do not call for help or lock onto a structure.
- **Our minions' aggro (standard rules, owner 2026-10-20):** a unit attacks, in order: whoever damaged it (enemy unit **or tower**), chasing while that attacker is within 32 studs (`RetaliateRange`, beyond tower range 28); the structure it is already hitting; the nearest enemy unit in aggro range; the nearest enemy hero in aggro range; the nearest unlocked enemy structure in aggro range (measured to its side). **Call for help:** when a unit is hit, same-team units within 10 studs (`HelpRange`) that are not already fighting back join in on the attacker.
- **Swarm movement** (`src/server/SwarmField.luau` + `Minions.server.luau`): no lanes or routes. The server keeps flow fields on a 4-stud grid (shortest walking distance around walls and structures, rebuilt when a structure falls). Units walk downhill on their field, plus **separation** (same-team units within 3.5 studs push apart) and a slowly changing sideways **wander**, so the horde fans out over open ground, flows around obstacles and converges on the openings. **Spread-out charge (owner 2026-10-21):** each zombie first walks to its own rally point, 30–65% of the way from its spawn to the Base Core and anywhere within 120 studs either side of the middle line (`ZombieRallyMinShare` / `ZombieRallyMaxShare` / `ZombieRallyHalfWidth`), so the horde covers the field instead of taking the shortest line; it drops the rally point within 8 studs of it or once it is already nearer the base. It then picks a base opening weighted 1/distance² from its rally point (zombies rallying on one side mostly use that side's opening). The flow-field grid now covers x -160..252, z ±188 (to the forest belt) so it reaches the core. Our minions follow a field to the nearest zombie core. A unit with an enemy in aggro range leaves the field, closes in while still spreading out and surrounds the target instead of stacking; units standing to fight shuffle apart if packed.
- **Reuse:** the prototype minion system (`src/server/Minions.server.luau`) becomes the enemy system: wave spawner with an alive cap *(carried: cap 30)*, waypoint walking, sticky targets, 12-stud / 3 s leash, retaliation within 20 studs, smooth turning (270°/s), melee and ranged types (the archer's draw-then-arrow attack, damage on arrival), full player size. Pathing (2026-10-20): flow fields when no enemy; when chasing an enemy, straight only if the line is open on the grid, else a short A* detour; drift never steers into obstacles; a unit that stops progressing steers plainly for 2.5 s.
- **Targets:** enemies attack players, walls (and other built structures) and the Base Core. Current rule: nearest enemy of any kind in aggro range (see Zombie aggro), else walk the flow field toward the core. Whether built walls/turrets/traps change this stays **OPEN** until T13.
- **Waves:** replaced by continuous spawning (owner 2026-10-21). Next slices (agreed plan): match timer and win/loss/reset, frontline pressure (Low/Medium/High reinforcements, with hysteresis), time escalation of zombie stats, Zombie Surge events. Numbers placeholder.
- **Boss:** the final wave of the full version is a boss. Design **OPEN**.
- **Zombie variants (owner 2026-10-21; placeholder numbers in `src/shared/Config.luau` `BRUTE` / `SPITTER`):** each zombie slot in a group may roll a variant (`Config.Minion.ZombieVariants`: Brute 10% (owner 2026-10-23: 10%, then 5%, back to 10%), Spitter 15%, else a normal zombie), **but only after that variant has arrived** (owner 2026-10-23): the match starts with plain zombies only; **The Brutes Arrive** at 3:00 and **The Spitters Arrive** at 6:00 (owner 2026-10-23, were 4:00 / 8:00) (`Config.Events.Arrivals`), each a one-time banner, not part of the random event rotation. Nest guards are plain zombies until the Brutes arrive. Same Gold/XP per kill as a zombie for now. **Look (owner 2026-10-23, different per kind):** no face, glowing red eyes at the head's eye height, Fabric clothes and small flat details. Zombie: Concrete skin, blood streaks on the shirt, rot patches on an arm and the left cheek, blood from the mouth. Brute: Slate hide, a stitched scar down the face, scars across both upper arms, a rope belt (shirt tears removed, owner 2026-10-23). Spitter: Concrete skin, yellow pustules on head, arms and chest, green acid stains down the shirt, acid from the mouth. **Our soldiers** (owner 2026-10-23): Fabric uniforms and a leather belt; swordsmen wear a steel breastplate and shoulder plates, archers a leather vest with a quiver strap across the chest.
  - **Brute:** 1.5x the size (`scale`), 500 health (owner 2026-10-23, was 240) and twice a zombie's damage (24), slower (5.5 vs 8), reach 10 (owner 2026-10-22: 6, then 12, now 10); clearly darker than a zombie (owner 2026-10-23: deep olive skin, near-black red shirt, dark legs). Attacks with a **two-handed overhead smash** (owner 2026-10-22, replacing the bite and a one-arm swing): both arms swing up overhead, then slam down in front (`BruteSmashHitDelay` 0.5 s; per-frame rotation pattern on the shoulders, `Config.Minion.BruteSmashLook`, so the walk animation cannot hide it). **Single target** (owner 2026-10-22: no area damage, no dust ring): it hits its target if still within reach; if that is one of our soldiers it is thrown back (`knockback` 56 studs/s: 28, tripled to 84, then 2/3; stunned `KnockbackStun` 0.5 s); heroes and buildings are not pushed.
  - **Spitter:** sickly yellow-green with a glowing green mouth; 70 health (owner 2026-10-23, was 90), range 20 (archers 16), one spit every 2.2 s. Rears back (`SpitWindup` 0.35 s, the swipe lunge), then lobs a green acid **blob** (40 studs/s) at the spot its target stood on and it **explodes on landing** (owner 2026-10-22: lands, does not follow), dealing 10 to every one of our units, heroes and buildings within 6 studs (`splashRadius`), so moving away in time dodges it. A spitter killed or stunned during the windup never spits. Clients show the lobbed blob and the green puddle it leaves (owner 2026-10-22, replacing a burst): a thin, flat (not glowing) puddle about as wide as the blast, shaped from a main splat and 4 smaller blots round its edge so it is not a circle; stays 2 s, fades over 1 s. Acid colour (owner 2026-10-22): a darker green, RGB 50, 140, 35, for the puddle, the blob and the spitter's mouth; display only, the damage is dealt once on landing (`ZombieAcid (spitter, from, landing, flightTime, radius)`, `MinionVisuals.client.luau`).

## Gold, building and repair
- **Gold** (owner 2026-10-20; **economy rework owner 2026-10-23**, aim: matches of 15-20 minutes): per player. **Every zombie death, killed by anyone, pays every player** (`Config.Gold.PerDeath`: Zombie 1, Spitter 2, Brute 4); the player whose hero lands the killing hit gets **+2 more** (`LastHitBonus`); a destroyed **Zombie Nest pays every player 40** (`PerNest`). Expected about 50-70 Gold a minute per player (to be checked with the Studio `[Economy]` per-minute Output log). Shown top right (`src/client/GoldCounter.client.luau`), with a gold "+N" rising from a zombie you finished (`GoldGained` event, sent only to you); server-owned in `src/server/Gold.luau` (Player attribute `Gold`). Every player starts with **0** (`Config.Gold.Starting`; the dev panel adds Gold for testing). Spent on base upgrades (below); kept for the session. Amounts and resetting per mission come with the mission flow.
- **Base upgrades (owner 2026-10-21; placeholder numbers in `Config.Base`):** the base has the **Base Core** (centre, 🛡️) and two **Barracks** (left ⚔️ and right 🏹; both labelled just "Barracks" since owner 2026-10-21, via a `DisplayName` attribute; the parts keep the ids `MeleeBarracks` / `ArcherBarracks`), the old inhibitors, now rectangular placeholders (12 x 8 x 16). ## Base Core
Single core per mission (health 1000, 1400 with the Fortified Core upgrade; see Base upgrades). Does not attack. Its health bar is always visible on the HUD. When it reaches 0 the mission is lost immediately; result committed once.

## HUD and presentation (PC first)
