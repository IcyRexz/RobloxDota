# UI design system

Owner decision 2026-10-21: **this is the one design standard for every piece of UI in the game.** New UI follows it; existing UI was restyled to it. The values live in code in `src/shared/UiTheme.luau`. Scripts read them from there and never hard-code their own fonts or colours. Change the theme file and everything follows.

**Blocky restyle (owner decision 2026-10-22).** The first version was minimal (see-through dark panels, no outlines, one gold accent). After comparing mockups the owner chose a bright, blocky Roblox-simulator look instead: solid gradient blocks with thick dark outlines, white text with a dark outline, chunky bars and big buttons. Menus keep the same layout (MenuKit); the HUD keeps its pieces but is bigger. Goal: bold, friendly and readable, while the HUD still leaves the battlefield clear.

## The six rules
1. **Two fonts:** **Fredoka One** (Roblox built-in) for titles, names, numbers and buttons (`Font.Bold`, `Font.Heavy`); **Builder Sans Bold** for body text and labels (`Font.Regular` = SemiBold, `Font.Medium` = Bold).
2. **Blocks:** every panel, card, tile, slot and button is a solid block: a top-to-bottom gradient fill, a thick **ink** outline (3 px in menus, 2 px on HUD pieces) and rounded corners (10 px; 16 px for whole menus). `UiTheme.block` / `styleBlock` make one; `setFill` / `setOutline` change it. Fills: **Navy** (HUD pieces, profile), **Blue** (menu body, cards), **Deep** (a darker blue for ability slots in the HUD and the Character menu; owner 2026-10-22: Blue was too bright there), **Sky** (the panel behind a grid; owner 2026-10-23: darkened to a calm inset a step darker than the body, the old pale sky was too bright; the Blue body and the Grey locked tiles were darkened the same day), **Gold** (selected, the menu rim, a waiting pick), **Green** (owned / taken, buy buttons, Gold chip), **Red** (close, warnings), **Light** (stat rows, tiles, info area; owner 2026-10-23: toned down, it was too bright), **Grey** (locked, cannot afford). A block's outline fades with its background.
3. **Outlined text:** white text with an ink outline (`UiTheme.text` adds it; thickness follows the size, size / 12 between 1 and 2.5 px (`UiTheme.outlineFor`; owner 2026-10-22: size / 8 filled in the holes of letters like o and e). On light blocks text is plain ink with no outline (`UiTheme.inkText`). The outline fades with the text. Hierarchy: size and font first, then white at three strengths (Value 0, Label 0.12, Faint 0.4 transparency).
4. **Colours with a fixed meaning:** gold = progress, rewards, selection and what you can do now (level, XP, Gold amounts, a waiting pick; owner 2026-10-22: improved stat values stay white); green = friendly health, owned / taken, buy; red = enemy health, damage you take, close and warnings; orange (`UiTheme.Improves`, darker since 2026-10-22 so it reads on light blocks) only for the "Improves: ..." line.
5. **Chunky bars with an ink outline** and a glossy fill: health 12 px, XP 8 px, structure 20 px, unit 6 px. The hero's own HUD health bar is 22 px with "current / max" inside it (owner 2026-10-22), like the structure bars; other bars keep their numbers beside them.
6. **Spacing in steps of 4 px** (`UiTheme.space(n)`).

## Not covered: things in the game world
Effects that are part of the world rather than the interface keep their own colours: the lightning bolt, arrows, tower shots, the red target ring on the ground, ability area markers, and the minimap's muted picture of the ground, fences, trees and rocks. Area markers on the ground use `src/shared/GroundRing.luau` (a dashed rim and faint fill whose pieces follow the ground's shape). Anything drawn as interface on top of the game (text, bars, panels, buttons, markers on the minimap) follows this system.

## Writing
Plain words, sentence case for sentences, short labels. Stats are named plainly: Health, Health Regen, Damage, Move Speed, Attack Speed, Range. Upgrades are **masteries**. Captions are short and may be uppercase (ATTRIBUTES).

## Where UI shows (owner 2026-10-23, plan slice 1)
Every screen belongs to a context: **Lobby**, **Battle** or shared (`docs/15_LOBBY_MATCHMAKING_PLAN.md` section 3 lists them). The server writes the Player attribute `GameContext`; `src/shared/GameContext.luau` reads it.
- A ScreenGui the script never opens or closes itself: `GameContext.showIn(screen, "Battle")` (or `"Lobby"`).
- A screen that opens and closes (menus, death and end screens): the script keeps `Enabled`, refuses to open outside its context and closes itself on leaving it (`GameContext.during`).
- Per-frame updates and polling loops run only in their context: `GameContext.renderStepped` / `GameContext.every`. Keys and clicks for battle actions check `GameContext.is("Battle")`.
- Camera and mouse icon per context live in `ContextCamera.client.luau` only (lobby: third person, free mouse; battle: first person, hidden icon).

## Process
- New or changed UI must use `UiTheme`: no raw fonts, colours or radii in UI scripts.
- If something truly needs a new token, add it to `UiTheme.luau` and to this doc in the same change, and record why in `TASK_STATUS.md`.
